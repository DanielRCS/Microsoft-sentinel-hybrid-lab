# Suspicious PowerShell Execution

## Purpose

This detection identifies suspicious PowerShell activity based on command-line patterns commonly associated with encoded, obfuscated, or script-based execution.

The goal is to detect PowerShell behavior that may be used for execution, payload decoding, or other potentially malicious activity.

---

## Data Source

- Microsoft Sentinel
- Windows Security Events
- Event ID 4688 - Process Creation
- Windows endpoint: COFFEE

---

## Detection Logic

The rule looks for `powershell.exe` or `pwsh.exe` process creation events and checks the command line for suspicious patterns such as:

- `FromBase64String`
- `Invoke-Expression`
- `IEX`
- `-EncodedCommand`
- `-enc`
- `DownloadString`
- `WebClient`

```kusto
SecurityEvent
| where EventID == 4688
| where NewProcessName endswith @"\powershell.exe"
    or NewProcessName endswith @"\pwsh.exe"
| where CommandLine has_any (
    "FromBase64String",
    "Invoke-Expression",
    "IEX",
    "-EncodedCommand",
    "-enc",
    "DownloadString",
    "WebClient"
)
| extend HostName = extract(@"^([^.]+)", 1, Computer)
| extend DnsDomain = extract(@"^[^.]+\.(.+)$", 1, Computer)
| project
    TimeGenerated,
    Computer,
    HostName,
    DnsDomain,
    Account,
    NewProcessName,
    ParentProcessName,
    CommandLine
| order by TimeGenerated desc
```

---

## Rule Configuration

- Name: `Suspicious PowerShell Execution`
- Severity: High
- Run Frequency: Every 5 minutes
- Lookback: 5 minutes
- MITRE ATT&CK Tactic: Execution
- MITRE ATT&CK Technique: T1059.001 - PowerShell

---

## Alert Details

### Alert Title

```text
Suspicious PowerShell execution on {{Computer}}
```

### Alert Description

```text
{{Account}} executed suspicious PowerShell activity on {{Computer}}.
```

---

## Custom Details

The alert includes:

- `Account`
- `ParentProcessName`
- `CommandLine`

These fields make it easier to quickly identify who ran the command, what launched PowerShell, and what command was executed.

**Device**

## Testing

The rule was tested using Atomic Red Team technique:

```text
T1059.001 - PowerShell
```

The Atomic test generated PowerShell activity containing:

```text
FromBase64String
IEX
```

The command also attempted to decode Base64 content and interact with registry and file artifacts.

Microsoft Defender interrupted the Atomic Red Team test before it completed successfully.

Even though the execution was blocked, Windows process creation telemetry still captured the suspicious PowerShell command line in Event ID 4688.

The detection successfully generated a High-severity Sentinel incident from this activity.

---

## Detection Behavior

The rule is based on suspicious PowerShell behavior rather than looking specifically for Atomic Red Team.

This means the same detection can identify similar activity generated by other tools or real attacker behavior if the command line contains the monitored patterns.

Normal PowerShell activity from services such as Azure Arc did not match the detection during testing because it did not contain the suspicious command-line indicators.

---

## Recommended Investigation

When this detection triggers:

1. Review the full PowerShell command line.
2. Identify the user that executed the command.
3. Review the parent process that launched PowerShell.
4. Check for related file or registry activity.
5. Review surrounding process creation events.
6. Determine whether the PowerShell activity was authorized.
7. If suspicious, investigate the endpoint and user account for additional activity.

---

## Result

The final detection successfully identified suspicious PowerShell execution generated during Atomic Red Team testing.

The test also showed that endpoint prevention and SIEM visibility can work together: Microsoft Defender interrupted the execution while Sentinel still captured enough process telemetry to investigate the attempted activity.
